## 组件与细节

- **定时任务区**（F31）：GET /jobs 全量按 task_id 聚合出定时任务（前端推导：
  同一 task_id 多条 job + params 含 interval_secs 即视为定时）；
  展示 名称（params 推导）/ 命令（mono 截断）/ 间隔（人类可读：每 1h/每 24h）/
  下次语义说明。注：后端无「暂停定时任务」API，此处只读展示（见 open-questions）。
- **执行历史**：行点击 → /jobs/:id；类型列从 task_id 有无 + kind 推导
  （快速/脚本/定时 label-12 徽标）；状态色字同全局规范。
- **[+ 定时任务]**（F30）：右抽屉表单：命令（mono）、参数、间隔（预设 chips：
  1m/5m/1h/6h/24h + 自定义秒数输入）；提交 POST /tasks/schedule →
  toast「已创建，Server 重启后自动恢复」。
- **[▶ 快速执行]**：跳转本机概览 tab 并聚焦命令输入（复用 F25，不在本页重复表单）。

## 状态矩阵

| 状态 | 表现 |
|------|------|
| Loading | 两区骨架 |
| 无定时任务 | 定时区整块隐藏（不留空白） |
| 无执行历史 | 历史区空态「还没有执行过任务」+ [快速执行] 按钮 |
| 状态过滤无结果 | 「没有 [失败] 状态的任务」+ 清除 chip |
| 主机离线 | 不拦截（历史只读）；[+ 定时任务] [▶ 快速执行] 禁用（下发不可达） |

## 交互细节

- job_id 显示前 4 位 mono + tooltip 全值；时间列相对时间（30s 重渲染）。
- 状态 chips 与 URL query 同步（?status=failed 可分享）。
